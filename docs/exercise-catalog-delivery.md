# 动作目录与 AI 计划交付说明

新版计划通过具体器材、经验和可用时间筛选动作，AI 只选择编号、用途和日期，程序从审核模板填入名称与用量。草案和正式计划可以预览现有教学、选择同用途和动作模式的替代项，替换保留计划动作 UUID。

## 目录与内容边界

唯一编辑源为 `Sources/SteadyCore/Resources/TrainingCollections/exercise-catalog.v1.json`。97 个教学引用完整归类为 85 个规范动作（23 个可编排、62 个仅供学习）和 4 个仅教学流程。目录包含 40 种器材、24 个训练模板，角色分为 12 个热身、9 个主练和 3 个整理模板。原课程正文、动画和来源标记保持原位。

[完整动作及模板清单](exercise-catalog-review.v1.json)逐项记录开放依据、未开放原因、教学来源及源文件哈希。尚无完整审核的下肢主练，完全无器材或只有哑铃也没有可用主练组合。当前目录不能用于宣称完整均衡的全身计划；AI 无法满足目标时返回条件不足。演示模式提供固定练习样例，并明确标注演示。

运行 `node scripts/export-exercise-catalog.mjs` 生成后端 TypeScript 文件；禁止手工维护生成文件。提交前执行 `node scripts/export-exercise-catalog.mjs --check` 和 `node --test scripts/exercise-catalog.test.mjs`。Swift 在读取同一 JSON 时计算 SHA-256。当前两端内容哈希为 `86292e526103697d6e9ac58f4199062b325fddbd214183ca7b7517ae251207d4`。已发布的动作和模板身份应保持稳定，内容变更需升级目录版本，避免改变历史快照含义。

## 保存与同步

新字段全部可选，旧计划无需迁移。动作名称和处方为历史快照。用户修改处方后清除模板绑定，保留教学；替换使用该计划保存的器材与经验条件，重新验证完整预算。自定义处方无法自动估时，需恢复模板才能自动替换。

旧端省略字段时，由原 `sync_push` 事务按动作 UUID 合并；显式 null 表示新端主动清除。旧端改名清除关联、改处方清除模板、删除动作不恢复。器材场景不变时保留旧选择，切换场景则要求重新确认。未知历史编号保留文字和元数据，不猜测教学入口，也不允许用于新 AI 编排。

客户端也按字段保留旧 JSON 的缺省状态：旧版离线数据升级后，修改日期、反馈和普通偏好不会把未知字段转换为 null。主动赋值或清除才输出相应值或 null；修改处方仅清除模板绑定。该状态只影响编码，不增加云端字段，也不参与领域对象相等比较。

## 发布步骤

1. 应用 `supabase/migrations/20261010064146_plan_catalog_compatibility.sql`，保留现有冲突检测与同步端点。
2. 同批部署依赖共享 schema 的 `consents`、`sync-pull`、`sync-push`、`chat`、`report` 和 `plan-draft`，包含生成后的目录。不要仅更新计划生成函数。
3. 发布含新目录和器械确认功能的客户端，验证线上同步与真实 AI 契约。
4. 最后设置 `STEADY_PLAN_CATALOG_ENABLED=true`。默认关闭；旧请求仍走旧版生成路径，新请求在关闭时显示暂未开放。

回退时关闭新版生成开关，保留新增同步字段、兼容合并和已生成计划的读取能力。

## 验收与环境

生产项目已通过 Supabase 插件只读核实为 `steady-internal`，与 App 配置一致。本次未修改生产服务，也未安装真机。测试使用独立本地数据库和专用 iOS 模拟器，原有项目的容器和数据未重置。

最终测试结果与模拟器证据见 `verification/plan-catalog-2026-10-10/`。本地 HTTP 测试使用临时合成账户，不调用真实 AI；模拟器通过不代表真机或正式 AI 服务验收。
